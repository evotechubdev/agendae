Pré-requisitos

  • Estabelecimento cadastrado e publicado no AGENDAE.
  • Acesso de gerente à aba API do estabelecimento.
  • Acesso às variáveis de ambiente dos dois backends no Render.
  • Uma rota pública no backend do site cliente para funcionar como proxy.

Responsabilidade de cada sistema

ComponenteResponsabilidade
AGENDAECadastro da loja, serviços, profissionais, horários, modalidade e reservas.
Backend AGENDAEAutentica a chave e disponibiliza catálogo, horários e criação de agendamento.
Backend do clienteProtege a chave e encaminha somente as rotas necessárias ao frontend.
WidgetApresenta a interface e conversa com o proxy do cliente.
2
CHAVE E BACKENDS

1. Gerar e configurar a chave

1

Abra a aba API

No painel do estabelecimento, entre em Configurações da loja → API e use Gerar e salvar chave.

2

Copie nome e valor

A chave é mostrada uma única vez. Guarde o nome da variável e o valor secreto em local seguro.

3

Cadastre nos dois backends

Use exatamente o mesmo nome e o mesmo valor no backend AGENDAE e no backend do cliente.

API_AGENDAE_{SLUG_EM_MAIÚSCULAS}=ag_live_...

Exemplo para um estabelecimento com slug octn:

API_AGENDAE_OCTN=ag_live_...
Após alterar variáveis no Render:

faça o deploy de cada backend. O plano gratuito não exige Shell; use Manual Deploy → Deploy latest commit.

Nomes para outros estabelecimentos

SlugVariável
octnAPI_AGENDAE_OCTN
salao-belaAPI_AGENDAE_SALAO_BELA
clinica-centroAPI_AGENDAE_CLINICA_CENTRO

URL privada da loja no AGENDAE

https://agendae-backend-t5ax.onrender.com/v1/establishments/{slug}

O frontend não deve chamar essa URL diretamente, porque isso exigiria expor a chave. Ele chama o proxy do backend cliente.

3
PROXY SEGURO

2. Preparar o backend do cliente

Crie um proxy com três rotas públicas. Em cada chamada servidor a servidor, acrescente o cabeçalho de autorização.

Rota no clienteDestino no AGENDAEMétodo
/api/agenda/catalog/catalogGET
/api/agenda/availability?.../availability?...GET
/api/agenda/appointments/appointmentsPOST

Exemplo de função no Node.js

const AGENDAE_BASE =
  "https://agendae-backend-t5ax.onrender.com/v1/establishments/SEU_SLUG";
const API_KEY = process.env.API_AGENDAE_SEU_SLUG;

async function agendaeRequest(path, options = {}) {
  const response = await fetch(`${AGENDAE_BASE}${path}`, {
    method: options.method || "GET",
    headers: {
      Accept: "application/json",
      Authorization: `Bearer ${API_KEY}`,
      ...(options.body ? { "Content-Type": "application/json" } : {})
    },
    body: options.body ? JSON.stringify(options.body) : undefined
  });
  const data = await response.json();
  if (!response.ok) throw new Error(data.message || "Falha no Agendae");
  return data;
}

Campos permitidos no POST

{ "date", "time", "professional", "service", "client", "phone" }
Recomendação:

valide formato e tamanho dos campos, limite o corpo JSON, defina timeout para a API e permita CORS somente para o domínio público do cliente.

Não faça:

não devolva a chave no JSON, não registre o cabeçalho Authorization em logs e não aceite uma chave enviada pelo navegador.

FRONTEND E BOTÃO

3. Instalar a interface no site

1

Copie o arquivo

Coloque o arquivo baixado em uma pasta pública do site:

<raiz-pública>/integracoes/agendae-booking-widget.js
2

Adicione o botão

O botão pode ficar no cabeçalho, menu ou conteúdo. O atributo abaixo é obrigatório:

<button type="button" data-agendae-open>
  Agendamento
</button>
3

Carregue o widget

Inclua antes de </body>. A URL deve apontar para o backend do cliente:

<script
  src="/integracoes/agendae-booking-widget.js"
  data-agendae-api="https://BACKEND-DO-CLIENTE/api/agenda"
  data-agendae-establishment="NOME DO ESTABELECIMENTO"
  defer
></script>

Configurações disponíveis

AtributoUso
data-agendae-apiObrigatório. URL pública do proxy, sem barra final.
data-agendae-establishmentNome opcional. Se omitido, usa o catálogo.
data-agendae-logoURL alternativa para a logomarca do AGENDAE.
data-agendae-open-selectorSeletor alternativo; o padrão é [data-agendae-open].

A abertura também pode ser controlada por código:

window.AgendaeBooking.open();
window.AgendaeBooking.close();

CONFIGURAÇÕES E VALIDAÇÃO

4. Modalidades vindas do AGENDAE

O site cliente não escolhe o funcionamento da agenda. O widget recebe essas configurações no catálogo da API.

CampoValorComportamento
bookingModescheduledAgendamentos e senhas com escolha de datas futuras.
dailySomente senhas diárias; usa hoje e bloqueia a troca da data.
scheduleModeemployeeCada profissional possui seus próprios horários.
establishmentUma única grade é compartilhada pela equipe.
Onde alterar:

bookingMode é escolhido em Configurações da loja → Dados do estabelecimento → Modalidade de atendimento. É necessário clicar em Salvar dados da loja.

Checklist antes da entrega

  • O mesmo nome e valor da variável existem nos dois backends.
  • Os dois serviços foram publicados depois da configuração.
  • A chave não aparece no HTML, JavaScript ou repositório público.
  • O widget está em /integracoes/agendae-booking-widget.js.
  • O botão possui data-agendae-open.
  • data-agendae-api aponta para o backend do cliente.
  • Catálogo, horários e confirmação foram testados no ambiente online.

Teste rápido

  1. Abra o site cliente e clique em Agendamento.
  2. Confirme logomarca, serviços e data esperada.
  3. Escolha um horário, informe nome e telefone e finalize.
  4. Verifique se a reserva apareceu no painel do estabelecimento no AGENDAE.

SOLUÇÃO DE PROBLEMAS

Diagnóstico rápido

Mensagem ou sintomaO que conferir
“Integração ainda não está configurada”Nome da variável, formato ag_live_... e deploy dos dois backends.
Erro 401 ou 403Os valores da chave são idênticos e a rota contém o slug correto.
Erro 502 ou 504O Render gratuito pode estar despertando. Aguarde alguns segundos e tente novamente.
Botão não abreArquivo carregado sem erro, atributo data-agendae-open e caminho do script.
Serviços ou horários não aparecemLoja publicada, serviços ativos, escalas e expediente configurados no AGENDAE.
Data está bloqueada em hojebookingMode está como daily. Isso é esperado para senhas diárias.

Ordem segura para trocar uma chave

  1. Gere a nova chave na aba API do estabelecimento.
  2. Atualize o backend do cliente com o novo valor.
  3. Publique os dois backends e confirme o catálogo.
  4. Nunca mantenha a chave em arquivos do frontend.
Integração concluída

Quando o catálogo carregar, os horários forem consultados e uma reserva de teste aparecer no AGENDAE, o site cliente já está operando pela API.
